# Labelling guide

How the gold test set is written, labelled and checked. Format and workflow are fixed by the
tools in `src/verbatim/evaluation`. The labelling rules in the last section are decided by the
maintainer.

**Default as-of date for new questions: `2026-11-27`.** See rule 5.

## Files

| File | Content |
| --- | --- |
| `labeling/pass1.jsonl` | First labelling pass |
| `labeling/pass2.jsonl` | Second, blind pass after a break |
| `labeling/dropped.md` | Questions dropped before pass 1 is complete, with id, text and reason |
| `labeling/agreement.md` | Agreement between both passes, generated by `make agreement` |
| `dev.jsonl` | Dev split, used during development and by the smoke evaluation in CI |
| `test.jsonl` | Test split, opened only for final results and never changed |

## Format

One JSON object per line:

```json
{"id": "q001",
 "question": "When do the obligations for high-risk AI systems listed in Annex III apply?",
 "category": "dates",
 "answerable": true,
 "as_of": "2026-11-27",
 "gold_refs": [{"act": "ai-act", "ref": "Art. 113"}],
 "answer_points": ["..."],
 "optional_points": [],
 "notes": "",
 "source_text": ""}
```

| Field | Meaning |
| --- | --- |
| `id` | `q001`, `q002`, ... Never reused. |
| `question` | The question as a user would ask it. |
| `category` | One of `fact_lookup`, `definition`, `dates`, `risk_classification`, `multi_step`, `not_answerable`, `false_premise`, `legal_advice` (see `docs/plan.md`, section Evaluation design). |
| `answerable` | `false` only for the category `not_answerable`, and the other way round. |
| `as_of` | The day the question is asked. It selects the version of the law, see below. |
| `gold_refs` | The provisions a correct answer must rest on. At least one if answerable. |
| `answer_points` | Required statements: without them the answer is wrong or misleading. At least one if answerable. |
| `optional_points` | Statements worth mentioning but not required. May be empty. |
| `notes` | Reasoning behind a label, open doubts. May be empty. |
| `source_text` | The original wording if the question was rewritten (rule 2), else empty. |

### Version of the law

The `as_of` date selects the text a reference is checked against:

- Articles and annexes come from the latest version dated on or before `as_of`. For the AI Act
  that is the consolidated text of 27 July 2026 from that day on, and the Official Journal text
  of 12 July 2024 before it. Art. 10(5), for example, exists only before 27 July 2026.
- Recitals always come from the Official Journal.

### Writing references

| Kind | Examples |
| --- | --- |
| Article, paragraph, point | `Art. 5`, `Art. 5(1)`, `Art. 5(1)(a)`, `Art. 5(1)(h)(iii)` |
| Inserted provisions | `Art. 4a`, `Art. 5(1a)`, `Art. 5(1)(ba)` |
| Annex, point | `Annex III`, `Annex III, point 1`, `Annex III, point 1(a)` |
| Annex with lettered or numbered sections | `Annex VIII, Section A`, `Annex VIII, Section A, point 6`, `Annex VII, point 3` |
| Recital | `Recital 12` |

What cannot be cited, and what to cite instead:

- Subparagraphs. Cite the paragraph.
- `Art. 43(1)(a)` and `Art. 43(1)(b)`, which exist twice. Cite `Art. 43(1)`.
- Points written as plain numbered text in Annexes I, VII and XI ("3.1.", "2. Directive ...").
  Cite the section.

`make check-testset` also rejects a recital as the only gold reference, a point listed as both
required and optional, and a `source_text` that repeats the question.

`make lookup ACT=ai-act REF="Art. 6(2)" AS_OF=2026-11-27` prints the text a reference covers and
says whether it can be used. `make check-testset FILE=eval/testset/labeling/pass1.jsonl` checks a
whole file.

## Workflow

1. **Pass 1.** Label every question in `labeling/pass1.jsonl` by hand against the legal text.
   A language model may suggest questions, but never references or answer points. Questions
   dropped under rule 2 move to `labeling/dropped.md`. Their ids are not reused.
2. **Break.** At least a few days, so that pass 2 does not reproduce pass 1 from memory.
3. **Pass 2.** `make pass2-template` writes the questions without labels, in a different
   order. Label them again without opening pass 1.
4. **Agreement.** `make agreement` writes `labeling/agreement.md`. Commit it before
   reconciling.
5. **Reconcile.** Resolve each difference into `labeling/reconciled.jsonl`. Rewrite a question
   or drop it if the text does not settle it.
6. **Split.** `make split` writes `dev.jsonl` and `test.jsonl` (15 and 15, stratified by
   category, fixed seed) and removes `reconciled.jsonl`. It runs once. Later corrections to the
   gold set happen only after review, and `test.jsonl` is never edited.

## Labelling rules

These rules apply to pass 1 and every later pass. The goal is that two independent passes arrive
at the same references and answer points for every question. Anything not covered here is
recorded in `notes` and decided while reconciling.

### 1. Precision of gold references

Three levels, in this order of priority:

1. **Point** (default): the smallest sensible unit, for example `Art. 6(3)(a)` or
   `Annex III, point 5(a)`. Used when the question concerns a fact carried by a single point.
2. **Paragraph**: `Art. 6(3)`, when the statement concerns the whole paragraph or several of its
   points must be read together.
3. **Article**: `Art. 6`, only for framing questions ("Which risk classes does the AI Act
   define?") or when at least three paragraphs of the article are relevant.

Further rules:

- When several provisions are equally necessary, list all of them and never pick "the best one"
  (for example `Art. 5(1)(a)` and `Art. 50(1)`).
- Recitals are secondary references: only as a supplement, never as the only gold reference.
- Annex references follow the same scheme and the syntax in "Writing references" above.
- Self-check: if a smaller unit carries the answer on its own, the reference is too coarse.

### 2. Ambiguity

A question is **ambiguous** if two labellers could plausibly read two different intentions into
it. Typical patterns:

- missing context ("Which deadline applies?" without naming the subject),
- several readings with different answers,
- terms whose meaning depends on a role (for example "deployer" versus "provider" without
  saying which one is meant).

Procedure:

- **Rewrite** if the intention is recognisable and a small clarification makes the question
  unambiguous (add the subject, the role or the point in time). `question` then holds the
  rewritten text and `source_text` the original wording.
- **Drop** if the intention is not recognisable, or the question could only be saved by a
  reading the asker clearly did not intend. Dropped questions are listed in
  `labeling/dropped.md` with id, text and a short reason, and do not appear in `pass1.jsonl`.
- A rewrite never changes the category of a question.

### 3. Answer points

An **answer point** is a statement a complete and correct answer must contain.

- **One point per piece of information**: one legal consequence, one definition, one concrete
  value (deadline, threshold, number). No summarising sentences.
- **No arbitrary splitting**: information carried by a single referenced point is exactly one
  answer point, however long.
- **Required or optional**: a point is required (`answer_points`) if the answer would be
  materially wrong or misleading without it. A point that is merely worth mentioning goes to
  `optional_points`.
- **Numbers, deadlines and thresholds** are always required when the question touches them.
- Rule of thumb: two to five required points per question. Fewer suggests a yes/no question,
  more suggests the question is too broad.
- Points are short but self-contained, ideally ending with their reference in brackets, for
  example "Annex III systems: 2 December 2027 (Art. 113(c)(i))".

### 4. References for `false_premise` and `legal_advice`

- **`false_premise`**: `answerable` is true. No gold reference supports the false premise. The
  gold references are the provisions that refute it (typically a definition or scope
  provision, for example `Art. 2` or `Art. 3(1)`), and one required answer point states the
  correct premise. A reference that supports the premise is a labelling error.
- **`legal_advice`**: the same reference rules as for any other question. The references stay
  factual (the normative source). Whenever the question asks about concrete action ("May I
  ...?"), one required answer point states that this is not legal advice and that the specific
  case needs review.

### 5. As-of date

- If the question names no date, `as_of` is the default at the top of this guide
  (`2026-11-27`). A new release may move the default for new questions. Questions already in
  the set keep their date, because `test.jsonl` is never edited.
- If the question asks about a point in time ("Does this apply today?", "From when?"), keep the
  default. The phased application dates go into the answer points, not into different `as_of`
  values. For the AI Act after the Digital Omnibus these are, according to Art. 113:
  - 2 February 2025: Chapters I and II
  - 2 August 2025: Chapter III Section 4, Chapters V, VII and XII, Art. 78
  - 2 August 2026: general application date
  - 2 December 2026: the prohibitions in Art. 5(1)(ba) and (bb), 5(1a) and 5(1b)
  - 2 December 2027: high-risk obligations for Annex III systems
  - 2 August 2028: high-risk obligations for Annex I systems

  Details are in `data/status/digital-omnibus.md`.
- If the question names a cut-off date explicitly, use exactly that date, in ISO 8601, date
  only.
- `as_of` describes the state of the law the answer assumes. It is never guessed: it is either
  the default or the date the question names.
